Prediction Engine Mechanics & Methodology
01
Solar Power Sampling

Calculates effective irradiance modulated by lunar topography, surface elevation angles, and terrain shadow penalties using non-linear derating factors.

02
Subsystem Demand Summation

Aggregates active power draws across Critical (life support, thermal), Important (navigation, sensors), and Deferrable (experiments) habitat rings.

03
Forward Coulomb Integration

Integrates discrete $\Delta t$ time steps across a 360-minute window accounting for 92% Coulombic charge and 95% discharge round-trip cell efficiency.

04
Reserve Threshold Intersection

Identifies exact predicted minute when storage crosses the mandatory 10% safety reserve and triggers proactive load-shedding guidance.

About ShadowSignal

AI-Powered Lunar Habitat Energy Survival Simulator

ShadowSignal is a Space Tech hackathon prototype demonstrating how intelligent energy management could protect future lunar habitats from power shortages caused by terrain shadows, fluctuating solar illumination, and variable energy demand.

The application simulates solar generation, battery storage dynamics, habitat energy consumption, shortage prediction, and intelligent load-shedding recommendations — all running locally without any external services.

⚠ Simulation Prototype — All values are demonstration data, not real lunar measurements.
Architecture
  • Frontend: HTML5, CSS3, JavaScript (Chart.js, Lucide Icons)
  • Backend: Python / Flask REST API
  • Simulation: Deterministic physics-based engine (NumPy)
  • Prediction: Forward energy simulation with configurable time steps
  • Communication: REST API — polling every 800 ms while running
Demo Sequence
  1. Open dashboard — habitat running under normal sunlight.
  2. Start simulation — observe solar generation and battery charge.
  3. Switch to Partial Shadow — watch solar output drop.
  4. Switch to Severe Shadow — energy shortage predicted.
  5. Generate Survival Plan — review load-shedding recommendations.
  6. Accept actions — observe extended battery endurance.
  7. Reset — restore original state.
Assumptions & Limitations
  • Solar output model is a simplified power fraction, not a geometric ray-tracing model.
  • Battery modelled as a perfect single-compartment cell with fixed charge/discharge efficiency.
  • Habitat demand is held constant within a scenario — no stochastic load variation.
  • Forecasts assume current conditions persist unchanged throughout the prediction window.
  • No real lunar sensor data is used. This is a demonstration prototype.
